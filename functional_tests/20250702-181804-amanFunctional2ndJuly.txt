### Test Cases for ZBIO-6550  
Below is a structured list of **Functional** and **Non-Functional** test cases for the user story described in the ticket.  

---

#### **Functional Test Cases**

##### **1. Test the updated structure of `advancedDetails` object**  
- **Input Values:**  
  - `advancedDetails` object with valid structure as per the new format.  
    ```json
    {
      "skippedMethods": 6, 
      "existingTestPresent": 0, 
      "notSupported": 4, 
      "toBeProcessed": 2,
      "totalTestFiles": 12,
      "successfulTests": 5,
      "testsWithRunTimeErrors": 2,
      "testsWithCompilationErrors": 7
    }
    ```  
- **Expected Output:**  
  - The application correctly utilizes `advancedDetails` data (e.g., shows metrics such as `Generated` column).  
    ```
    * 12 Test (for 14 methods) *
    ```
  
- **Edge Cases:**  
  - Provide invalid values (e.g., null or missing fields) in `advancedDetails`. Expect error handling in the API or frontend with an appropriate error message.  

---

##### **2. Remove `csvFileDetails` and `csvFiles` objects from the backend**  
- **Input Values:**  
  - Make API call where previously `csvFileDetails` and `csvFiles` were used. Update relevant code to pull data directly from `advancedDetails`.  
- **Expected Output:**  
  - Backend does not respond with `csvFileDetails` or `csvFiles` and shows seamless functionality using `advancedDetails`.  

- **Edge Cases:**  
  - Ensure no part of the system tries to access the removed objects (`null pointer exception` should not occur).  

---

##### **3. Indexes replaced with scenario names in Integration Tests**  
- **Input Values:**  
  - Integration data with scenarios such as:  
    ```json
    [
      { "methodName": "Error handling and validation", "status": "successfully_generated" },
      { "methodName": "Bulk operations", "status": "successfully_generated" }
    ]
    ```
- **Expected Output:**  
  - Scenario names such as `"Error handling and validation"` and `"Bulk operations"` appear in the table column instead of indexes (e.g., 1, 2, etc.).  

- **Edge Cases:**  
  - No `methodName` provided - the integration test should handle and display a fallback name gracefully (e.g., `"Unnamed Scenario"`).  

---

##### **4. Removal of `methodScanned`, `methodSuccess`, `methodFailed`, etc., replaced by `advancedDetails` metrics**  
- **Input Values:**  
  - Test backend and UI where new metrics `skippedMethods`, `successfulTests`, `testsWithRunTimeErrors`, etc., are calculated.  
- **Expected Output:**  
  - Calculations are correct. E.g., `Generated` column shows:  
    ```
    12 Test (for 14 Methods)  
    ```
    where `totalTests = totalTestFiles + existingTestPresent + toBeProcessed`.  

- **Edge Cases:**  
  - Zero values in all fields (e.g., `totalTestFiles = 0`) — Ensure display handles such cases gracefully without breaking.  

---

##### **5. Integration Tests for New UI display (empty data issue)**  
- **Input Values:**  
  - Trigger an integration test where backend data returned is empty:  
    ```json
    { "advancedDetails": {} }
    ```  
- **Expected Output:**  
  - Display appropriate message on UI such as:  
    ```
    "No data found, please try again later."
    ```  

---
