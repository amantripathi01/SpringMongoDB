### Functional Test Cases

#### Scenario: AdvancedDetails structure changes
- **Objective**: Ensure `AdvancedDetails` structure changes are properly implemented and functional in the `approost` application.
- **Input**: Use the updated `AdvancedDetails` data structure sample:
  ```
  {
    "skippedMethods": 6,
    "existingTestPresent": 0,
    "notSupported": 4,
    "toBeProcessed": 2,
    "totalTestFiles": 12,
    "successfulTests": 5,
    "testswithRunTimeErrors": 2,
    "testWithCompilationErrors": 7
  }
  ```
- **Expected Output**: 
  - `AdvancedDetails` structure data is retrieved correctly.
  - All methods reference correct metrics from `AdvancedDetails`.
  - Other redundant objects such as `csvFilesDetails` and `csvFiles` are not referenced in the implementation.
- **Edge Cases**:
  - Empty `AdvancedDetails` data should not break the application.
  - Missing fields in `AdvancedDetails` should display an appropriate error or fallback behavior.

#### Scenario: Removal of csvFileDetails and csvFiles objects
- **Objective**: Verify redundant objects, `csvFileDetails` and `csvFiles`, are removed correctly and no backend functionality depends on them.
- **Input**: 
  - Access endpoints linked to the `AdvancedDetails` structure.
  - Test backend responses and logs to ensure no dependency on `csvFileDetails` and `csvFiles`.
- **Expected Output**: 
  - Application functions as expected utilizing only the `AdvancedDetails` object without errors.
- **Edge Cases**:
  - Any references to removed objects should result in appropriate error logs or messages.

#### Scenario: Generated column calculations
- **Objective**: Validate the values displayed in the `Generated` column are correct based on the provided formula:  
  ```
  totalTestFiles / totalTests (totalTestFiles + existingTestPresent + toBeProcessed)
  ```
- **Input**: Example data:  
  ```
  {
    "totalTestFiles": 12,
    "existingTestPresent": 2,
    "toBeProcessed": 3
  }
  ```
- **Expected Output**:
  - Generated column displays:  
    ```
    *12 Tests (for 17 Methods)*  
    ```
  - Ensure values update dynamically depending on data changes.
- **Edge Cases**:
  - Division by zero when all metrics are zero should be handled gracefully (e.g., `0 Tests (for 0 Methods)`).

#### Scenario: Data integration issues (empty table and incorrect indexes display)
- **Objective**: Ensure integration tests display appropriate data without showing empty tables or incorrect index names instead of scenario names.
- **Input**: Simulate integration tests with updated `AdvancedDetails` and without `csvFilesDetails`.
- **Expected Output**:
  - The table correctly populates with data for all scenarios.
  - Scenario names are displayed instead of index numbers.
- **Edge Cases**:
  - Handle cases where no data is available gracefully (e.g., display `No data found` message).
  - Ensure mixed valid and empty data scenarios populate the table correctly.

#### Scenario: Backend compatibility
- **Objective**: Verify `approost` changes are compatible with backend updates (ZBIO-6580).
- **Input**: Use the updated endpoints from backend for validation.
- **Expected Output**:
  - Compatible behavior between frontend (`approost`) and backend changes (`AdvancedDetails` structure).
- **Edge Cases**:
  - Ensure backward compatibility with older backend structures for unsupported environments.
